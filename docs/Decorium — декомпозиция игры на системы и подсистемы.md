# Decorium — декомпозиция игры на системы и подсистемы

Статус: draft v1  
Область применения: игровая концепция Decorium, MVP и дальнейшее развитие проекта.  
Цель документа — зафиксировать разбиение игры на глобальные системы и подсистемы, чтобы разработка шла по слабосвязанным модулям через инверсию зависимостей, вертикальные слайсы и TDD.

---

## 1. Принципы декомпозиции

Игра рассматривается как набор глобальных систем, каждая из которых содержит подсистемы. Системы взаимодействуют через контракты, порты, use-case API и события, а не через прямую реализацию.

Основные принципы:

1. Одна система — одна область ответственности.
2. Подсистемы внутри системы могут быть разделены по слоям:
   - Domain — правила и модели;
   - Application — сценарии использования;
   - Infrastructure — адаптеры, загрузка данных, внешние сервисы;
   - Presentation — отображение и ввод.
3. Системы не должны знать внутреннюю реализацию друг друга.
4. Оценка, прогрессия, экономика, UI и инфраструктура не смешиваются.
5. Все адаптивные и персонализированные механизмы должны быть детерминированными и воспроизводимыми.
6. Система не должна зависеть от реального мира как источника бизнес-логики.
7. Случайность допускается только через явный seed.
8. Состояние игрока выносится во внешнее хранилище, а исполняющие сервисы проектируются как максимально stateless.

# 3. Подробная декомпозиция систем

---

## 3.1. Game Flow и жизненный цикл сессии

### Назначение

Управляет тем, в каком состоянии находится игровая сессия, какие экраны и фазы активны, как игрок переходит от выбора уровня к расстановке, оценке и обратной связи.

### Подсистемы

1. **Session State Machine**
   - управляет состояниями сессии;
   - состояния: `MainMenu`, `LevelSelect`, `Placement`, `Evaluation`, `Results`, `Reward`, `NextLevel`.

2. **Screen Flow Coordinator**
   - управляет переключением экранов;
   - решает, какой экран открыть следующим;
   - не содержит бизнес-логику.

3. **Use Case Dispatcher**
   - принимает команды игрока и передаёт их в соответствующие use-case;
   - примеры команд: `StartLevel`, `ConfirmPlacement`, `RetryLevel`, `ReturnToMenu`.

4. **Level Session Coordinator**
   - запускает уровень;
   - получает `LevelDefinition`;
   - готовит стартовое состояние комнаты и инвентаря;
   - завершает уровень после подтверждения.

5. **Gameplay Phase Controller**
   - управляет фазами внутри уровня:
     - расстановка;
     - подтверждение;
     - оценка;
     - показ результата.

6. **Transition Rules**
   - правила переходов между экранами и фазами;
   - проверка, можно ли завершить уровень, вернуться назад или перезапустить сессию.

7. **Session Events Publisher**
   - публикует события:
     - `LevelStarted`;
     - `PlacementConfirmed`;
     - `EvaluationCompleted`;
     - `LevelCompleted`;
     - `SessionAbandoned`.

### Входы

- выбранный уровень;
- команды игрока;
- результат оценки;
- данные прогрессии;
- данные экономики.

### Выходы

- текущая фаза сессии;
- команды для других систем;
- события жизненного цикла.

### Запрещено

- считать score;
- менять экономику;
- напрямую рисовать UI;
- хранить долгосрочный профиль игрока;
- генерировать уровни.

## 3.2. Ввод и взаимодействие

### Назначение

Преобразует действия игрока на ПК и мобильных устройствах в игровые намерения.

### Подсистемы

1. **Device Adapter**
   - адаптер для ПК;
   - адаптер для touch-устройств;
   - абстракция над платформенным вводом.

2. **Gesture Recognition**
   - тап;
   - свайп;
   - drag;
   - pinch;
   - поворот двумя пальцами;
   - жесты камеры.

3. **Input Intent Mapper**
   - преобразует сырой ввод в намерения:
     - `SelectItem`;
     - `PlaceItem`;
     - `MoveItem`;
     - `RotateItem`;
     - `RemoveItem`;
     - `ConfirmPlacement`;
     - `Undo`.

4. **Selection Service**
   - выбор предмета из инвентаря;
   - выбор размещённого предмета;
   - снятие выделения.

5. **Placement Drag Controller**
   - перетаскивание предмета;
   - запрос позиции размещения;
   - взаимодействие с snapping-системой.

6. **Rotation Controller**
   - поворот предмета;
   - фиксация углов;
   - поворот с клавиатуры, мыши или жестом.

7. **Camera Control**
   - вращение камеры;
   - приближение и отдаление;
   - панорамирование;
   - адаптация под одну руку на мобильных устройствах.

8. **Snapping Request Service**
   - запрос прилипания к сетке;
   - запрос прилипания к поверхностям;
   - запрос выравнивания относительно стен и пола.

9. **Undo/Redo Command Buffer**
   - очередь отменяемых действий;
   - поддержка Undo для размещения, перемещения, поворота и удаления;
   - подготовка к будущему Redo.

10. **Input Accessibility Mapper**
   - переназначение управления;
   - упрощённые жесты;
   - альтернативные кнопки;
   - поддержка крупной зоны нажатия.

### Входы

- события мыши;
- события клавиатуры;
- touch-события;
- жесты;
- команды UI.

### Выходы

- игровые намерения;
- запросы к камере;
- запросы к snapping;
- события ввода.

### Запрещено

- принимать бизнес-решения;
- проверять стилевые ограничения;
- менять score;
- напрямую менять состояние комнаты без команды через application-слой;
- хранить прогресс игрока.

## 3.3. Состояние комнаты и пространственная симуляция

### Назначение

Хранит фактическое состояние размещённых предметов и предоставляет пространственные факты для оценки, ввода и отображения.

### Подсистемы

1. **Placed Item Registry**
   - список размещённых предметов;
   - добавление предмета;
   - удаление предмета;
   - обновление предмета.

2. **Transform State Model**
   - позиция;
   - поворот;
   - масштаб, если допускается;
   - привязка к поверхности.

3. **Room Bounds Model**
   - границы комнаты;
   - стены;
   - пол;
   - окна;
   - двери;
   - запрещённые зоны.

4. **Occupancy Grid**
   - сетка занятости;
   - занятые ячейки;
   - свободные зоны;
   - основа для проверки проходов и баланса.

5. **Spatial Query Service**
   - расстояния между предметами;
   - соседство;
   - блокировка проходов;
   - блокировка окон и дверей;
   - проверка зазоров.

6. **Collision/Overlap Adapter Port**
   - порт для движка коллизий;
   - адаптер для Unity Physics или другой физической подсистемы;
   - домен не должен зависеть от конкретной реализации.

7. **Zone Model**
   - функциональные зоны;
   - зона окна;
   - зона двери;
   - зона фокуса;
   - зона прохода.

8. **Room Snapshot Serializer**
   - сериализация состояния комнаты;
   - снимок для отладки;
   - снимок для replay;
   - снимок для сохранений, если требуется.

### Входы

- команды размещения;
- команды перемещения;
- команды поворота;
- команды удаления;
- параметры комнаты из уровня.

### Выходы

- `RoomState`;
- `PlacedItem`;
- пространственные факты;
- occupancy grid;
- snapshot комнаты.

### Запрещено

- считать стиль;
- считать эргономику;
- назначать штрафы;
- отображать предметы;
- хранить долгосрочный профиль игрока.

## 3.4. Каталог предметов и контентные метаданные

### Назначение

Описывает предметы как сущности предметной области и предоставляет их признаки для оценки, инвентаря, уровней и магазина.

### Подсистемы

1. **Item Definition Repository**
   - уникальный идентификатор;
   - название;
   - категория;
   - модель;
   - размеры;
   - цена;
   - теги;
   - статус доступности.

2. **Feature Vector Model**
   - нормализованные признаки предмета;
   - диапазон значений 0..1;
   - признаки цвета;
   - признаки материалов;
   - признаки геометрии;
   - признаки стиля;
   - функциональные признаки.

3. **Item Category Taxonomy**
   - мебель;
   - освещение;
   - декор;
   - хранение;
   - сидение;
   - зонирование;
   - текстиль;
   - растения и аксессуары.

4. **Style Tag Mapping**
   - принадлежность к стилям;
   - множественная принадлежность;
   - совместимость со стилевыми ограничениями.

5. **Dimension and Cost Model**
   - габариты;
   - занимаемая площадь;
   - нормализованный размер;
   - цена;
   - бюджетный класс.

6. **Item Availability Rules**
   - доступен ли предмет на уровне;
   - открыт ли предмет в прогрессии;
   - доступен ли предмет в магазине;
   - временные события, если появятся позже.

7. **Catalog Validator**
   - проверка уникальности id;
   - проверка полноты feature vector;
   - проверка нормализации признаков;
   - проверка ссылок на модели и теги.

8. **Catalog Versioning**
   - версия каталога;
   - миграции предметов;
   - совместимость сохранений;
   - отладочные фикстуры.

9. **Item Preview Adapter**
   - порт для получения превью;
   - миниатюры;
   - 3D-превью;
   - адаптер для UI, без бизнес-логики.

### Входы

- запросы уровней;
- запросы инвентаря;
- запросы магазина;
- запросы генерации уровней.

### Выходы

- `Item`;
- `FeatureVector`;
- списки доступных предметов;
- ошибки валидации каталога.

### Запрещено

- оценивать комнату;
- менять прогресс игрока;
- хранить текущее состояние комнаты;
- напрямую управлять UI.

## 3.5. Стилевые ограничения

### Назначение

Формализует требования стиля через линейные ограничения над вектором комнаты.

### Подсистемы

1. **Style Profile Catalog**
   - стили: Scandinavian, Loft, Modern и другие;
   - описание стиля;
   - приоритетные группы признаков;
   - набор ограничений.

2. **Linear Constraint Model**
   - вектор весов `a_i`;
   - оператор: `<=`, `>=`, `==`;
   - порог `b_i`;
   - группа ограничения;
   - вес штрафа.

3. **Constraint Grouping**
   - цвет;
   - материалы;
   - геометрия;
   - структура;
   - функциональные признаки.

4. **Constraint Evaluation Engine**
   - вычисляет:
     ```text
     value = dot_product(a_i, V_room)
     ```
   - сравнивает с порогом;
   - определяет нарушение.

5. **Style Violation Model**
   - идентификатор ограничения;
   - величина нарушения;
   - группа;
   - серьёзность;
   - ссылка на сообщение обратной связи.

6. **Style Penalty Calculator**
   - считает штраф:
     ```text
     penalty_i = max(0, b_i - value) для >=
     penalty_i = max(0, value - b_i) для <=
     penalty_i = abs(value - b_i) для ==
     ```
   - суммирует:
     ```text
     total_style_penalty = sum(penalty_i)
     ```

7. **Constraint Message Mapping**
   - связывает нарушение и конкретное сообщение;
   - пример:
     ```text
     scandinavian-wood-share-low → "Мне не хватает натуральных материалов, добавьте деревянную мебель."
     ```

8. **Constraint Variation Policy**
   - используется генератором уровней;
   - вариация порогов в допустимом диапазоне;
   - например:
     ```text
     b_i' = b_i + random(-0.1, +0.1)
     ```

9. **Constraint Catalog Validator**
   - проверка корректности ограничений;
   - проверка существования признаков;
   - проверка операторов;
   - проверка уникальности id.

### Входы

- `RoomVector`;
- стиль уровня;
- набор ограничений;
- параметры вариативности.

### Выходы

- список стилевых нарушений;
- `total_style_penalty`;
- диагностические данные.

### Запрещено

- считать эргономику;
- показывать UI;
- менять предметы;
- генерировать уровни без отдельного use-case;
- принимать решения о наградах.

## 3.6. Эргономические ограничения

### Назначение

Проверяет функциональность, удобство и пространственную организацию комнаты.

### Подсистемы

1. **Clearance Rule Engine**
   - минимальные проходы;
   - проверка расстояний между предметами;
   - проверка возможности перемещения игрока/взгляда;
   - целевые значения из GDD: примерно 36–40 дюймов для проходов, где применимо.

2. **Door and Window Access Rules**
   - нельзя блокировать двери;
   - нельзя блокировать окна;
   - расстояние до важных элементов;
   - доступ к функциональным объектам.

3. **Furniture Scale Relation Rules**
   - соотношение высоты стола и сиденья;
   - соотношение размеров мебели;
   - соразмерность предметов комнате;
   - проверка масштаба.

4. **Visual Balance Grid Analyzer**
   - деление комнаты на сетку, например 3x3;
   - оценка занятости ячеек;
   - дисперсия занятых площадей;
   - штраф за перегруженность одной зоны.

5. **Functional Zoning Rules**
   - наличие необходимых функциональных зон;
   - логичность группировки мебели;
   - отсутствие пустых или перегруженных зон;
   - проверка композиции.

6. **Ergonomics Violation Model**
   - тип нарушения;
   - затронутые предметы;
   - зона;
   - величина нарушения;
   - сообщение обратной связи.

7. **Ergonomics Penalty Calculator**
   - суммирует эргономические штрафы;
   - передаёт результат в scoring.

8. **Accessibility Expert Rules**
   - будущие правила доступности;
   - ADA-подобные сценарии для экспертных клиентов;
   - расширенные требования к проходам и доступу.

### Входы

- `RoomState`;
- occupancy grid;
- spatial query results;
- параметры комнаты.

### Выходы

- эргономические нарушения;
- `ergonomic_penalty`;
- диагностические данные.

### Запрещено

- считать стиль;
- менять предметы;
- отображать feedback;
- назначать награды.

## 3.7. Оценка и скоринг

### Назначение

Вычисляет итоговую оценку комнаты на основе стиля и эргономики.

### Подсистемы

1. **Room Vector Calculator**
   - вычисляет вектор комнаты:
     ```text
     Vroom = average(Vitems)
     ```
   - при необходимости поддерживает веса предметов в будущем.

2. **Style Score Calculator**
   - вычисляет:
     ```text
     score_style = exp(-lambda * total_style_penalty)
     ```

3. **Ergonomics Score Calculator**
   - вычисляет:
     ```text
     score_ergonomics = exp(-lambda * ergonomic_penalty)
     ```

4. **Penalty Aggregator**
   - объединяет штрафы по группам;
   - готовит суб-оценки;
   - поддерживает диагностику.

5. **Score Weights Policy**
   - базовая формула GDD:
     ```text
     total_score = 0.7 * score_style + 0.3 * score_ergonomics
     ```
   - для MVP может быть режим:
     ```text
     total_score = score_style
     ```
     или вес эргономики `0.0`, если она временно отключена.

6. **Lambda Tuning Parameters**
   - коэффициент `lambda`;
   - настройки крутизны штрафной функции;
   - отдельные параметры для стиля и эргономики при необходимости.

7. **Star Rating Policy**
   - перевод `total_score` в звёзды:
     ```text
     1: < 0.4
     2: 0.4–0.55
     3: 0.56–0.70
     4: 0.71–0.85
     5: 0.86–1.0
     ```

8. **Sub-score Aggregator**
   - суб-оценки для radar chart:
     - цвет;
     - материалы;
     - геометрия;
     - структура/эргономика.

9. **Evaluation Result Builder**
   - собирает:
     ```text
     total_score
     score_style
     score_ergonomics
     star_rating
     sub_scores
     violations
     diagnostics
     ```

10. **Score Diagnostics and Explainability**
   - объяснение, почему оценка получилась именно такой;
   - какие ограничения нарушены;
   - какой вклад дал каждый штраф;
   - используется для debug и feedback.

### Входы

- `RoomVector`;
- стилевые нарушения;
- эргономические нарушения;
- параметры скоринга.

### Выходы

- `EvaluationResult`;
- star rating;
- sub-scores;
- диагностический отчёт.

### Запрещено

- отображать результат;
- генерировать комментарии;
- менять прогресс;
- начислять валюту;
- хранить долгосрочные результаты без persistence-системы.

## 3.8. Обратная связь и объяснение результата

### Назначение

Превращает математический результат оценки в понятную, конкретную и обучающую обратную связь.

### Подсистемы

1. **Evaluation Result Interpreter**
   - читает `EvaluationResult`;
   - выделяет проблемные группы;
   - определяет сильные стороны.

2. **Violation Prioritizer**
   - сортирует нарушения по влиянию;
   - выбирает самые важные;
   - ограничивает количество сообщений, чтобы не перегружать игрока.

3. **Feedback Message Catalog**

### Выходы

- подсказки.

## 3.10. Генерация уровней

### Назначение

Процедурно создаёт уровни на основе стиля, пула предметов, клиента, сложности и seed.

### Подсистемы

1. **Seed Provider**
   - предоставляет seed;
   - обеспечивает воспроизводимость;
   - поддерживает debug-режим с фиксированным seed.

2. **Difficulty Selector**
   - выбирает уровень сложности;
   - учитывает прогрессию;
   - учитывает целевую кривую сложности.

3. **Style Selector**
   - выбирает стиль из доступного пула;
   - учитывает клиентские требования;
   - учитывает прогрессию стилей.

4. **Item Pool Sampler**
   - выбирает набор предметов;
   - фильтрует предметы по тегам стиля;
   - обеспечивает достаточную возможность решить уровень.

5. **Constraint Variation Engine**
   - варьирует ограничения;
   - изменяет пороги в безопасном диапазоне;
   - пример:
     ```text
     b_i' = b_i + variation(-0.1, +0.1)
     ```

6. **Room Parameter Generator**
   - выбирает тип комнаты;
   - варьирует размеры;
   - задаёт окна и двери;
   - задаёт функциональные зоны.

7. **Budget Generator**
   - считает допустимый бюджет;
   - проверяет, что выбранные предметы укладываются в бюджет;
   - корректирует пул предметов при необходимости.

8. **Level Validator**
   - проверяет сгенерированный уровень;
   - проверяет решаемость;
   - проверяет отсутствие противоречий.

9. **Golden Fixture Generator**
   - создаёт фиксированные уровни для тестов;
   - сохраняет ожидаемые результаты;
   - помогает проверять детерминированность.

10. **Generation Diagnostics**
   - логирует seed;
   - сохраняет параметры генерации;
   - позволяет воспроизвести уровень.

### Входы

- seed;
- сложность;
- клиентский профиль;
- пул предметов;
- пул стилей;
- правила ограничений.

### Выходы

- `LevelDefinition`;
- сгенерированные ограничения;
- диагностические данные.

### Запрещено

- зависеть от реального мира;
- использовать недетерминированную случайность без seed;
- менять оценку;
- назначать награды;
- хранить долгосрочное состояние без persistence.

7. **Debug Panels**

   - отчёты по сохранениям.

9. **Performance Counters**

10. **Crash Adapter**

## 3.17. Персонализация и адаптация

### Назначение

Обеспечивает динамическую, но детерминированную адаптацию контента, сложности, обратной связи и поведения системы под игрока без зависимости от реального мира.

### Подсистемы

1. **Player Control Signal Model**
   - уникальный seed игрока;
   - клиентский тир;
   - предпочтения стиля;
   - уровень мастерства;
   - явные управляющие сигналы.

2. **Deterministic RNG**
   - генератор на основе seed;
   - одинаковый вход и seed дают одинаковый результат;
   - отсутствие скрытой случайности.

3. **Adaptive Difficulty Policy**
   - адаптация порогов;
   - адаптация сложности уровней;
   - адаптация бюджета;
   - адаптация количества предметов.

4. **Content Recommendation Policy**
   - подбор предметов;
   - подбор стилей;
   - подбор уровней;
   - рекомендации без реального внешнего мира.

5. **Feedback Style Policy**
   - тон комментариев;
   - подробность обратной связи;
   - строгость клиента;
   - поддерживающий или экспертный режим.

6. **Suffix Adapter**
   - опциональная адаптация LLM через суффиксы;
   - суффикс рассматривается как контрольный сигнал;
   - суффикс должен быть версионирован, документирован и тестируем;
   - запрет скрытого runtime-обучения.

7. **Compiled Artifact Validator**
   - если используется compiled AI подход;
   - LLM может генерировать артефакты offline;
   - артефакты проходят валидацию, тесты и review;
   - runtime исполнение должно быть детерминированным.

8. **Personalization Context Serializer**
   - сериализация контекста персонализации;
   - передача во внешнее хранилище;
   - восстановление при следующей сессии.

9. **No-Real-World Guard**
   - запрет использовать реальное время как источник логики, если это не разрешено явно;
   - запрет использовать внешние события как источник бизнес-решений;
   - все внешние зависимости только через явные порты.

### Входы

- seed;
- прогресс игрока;
- результаты уровней;
- настройки обратной связи;
- параметры сложности.

### Выходы

- персонализированный уровень;
- персонализированный feedback;
- адаптивные параметры;
- управляющие сигналы.

### Запрещено

- использовать недетерминированную случайность;
- зависеть от реального мира без явного адаптера;
- обучаться в runtime без отдельного архитектурного решения;
- скрыто менять правила скоринга.

# 9. Целевое правило разработки

Каждая новая функция должна быть явно привязана к одной глобальной системе и, при необходимости, к нескольким подсистемам.

Если изменение затрагивает несколько систем:

```text
1. Зафиксировать, какие системы затронуты.
2. Определить контракт между ними.
3. Разбить изменение на вертикальные слайсы.
4. Для каждого слайса написать тесты.
5. Обновить документацию затронутых систем.
```

Если изменение ломает границы систем:

```text
STOP
Reason: нарушается декомпозиция
Required decision: перенос ответственности или новый контракт
Recommended action: отдельный архитектурный слайс
```
